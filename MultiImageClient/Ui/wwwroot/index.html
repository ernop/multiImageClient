Which options apply where
  • output AR — without an input image, auto lets the model choose (grok-web can't do prompt-aware auto, so it defaults to square 1:1 there). Attach an image and that same default becomes match input image: gpt-image-2 and BFL derive source-matching dimensions; Grok, Ideogram, and Google choose the closest ratio their APIs accept. Any explicit choice overrides matching where the endpoint has an AR control. Recraft image-to-image inherently follows the source and has no size override, so Recraft disables for image jobs with an explicit AR.
  • detail — sets the resolution tier where one exists: gpt-image-2, grok-api (1k/2k), BFL (~1/~4 MP), Google (1K/2K/4K). This UI maps Ideogram 4.0 to its 2K-class resolutions; Recraft and gpt-image-1 are ~1K.
  • quality & moderation — OpenAI image models only.
  • n — OpenAI models and grok-api up to 10, Recraft up to 6, and Ideogram 4.0 / Ideogram 3.0 up to 8. Ideogram 4.0 performs separate single-image requests because its current API has no count field. BFL and Google return one; grok-web requests up to 4 in side-by-side mode; meta-web decides itself.
  • input images — gpt-image-2 and grok-api do true edits; Recraft runs image-to-image; Ideogram 4.0 uses Remix; Ideogram 3.0, BFL, and Google use the pasted image as a style/reference guide; grok-web edit rides the imagine WebSocket. Text-to-image-only targets (slashed icon) stay selectable but run from the prompt alone — the attached image is not sent to them. Only Recraft disables, and only for image jobs with an explicit AR it can't honor.
describe image → text — describes the attached image(s); your prompt is the instruction (blank = standard "describe this image"); output options above don't apply
